# 日本語の決まり（神野スタイル）

神野が登壇や勉強会、アップデート紹介のスライドで直してきた日本語の例を集めました。自分で書くときも、生成AIに原稿を頼むときも使えます。

ここに挙げた語や形を見つけても、本人が手で直した文は変えません。また、その分野で定着している技術用語（インバウンド認証など）は残します。普通の言葉に言い換えすぎると、エンジニアには逆に読みにくくなります。

`slides check` の `ai-phrase` は見出しやリード、本文にある表現に言い換えの候補を出します。「線を引く」「荷物を運ぶ」のように文脈を見て判断する語は表で確認します。図の中の文字も読み返してください。[自動検査の対象](../marp/scripts/phrases.json)

## 読点

読点はあまり入れません。神野の資料では、リードの半分近くの文に読点がありません。習慣で打った読点はAIの癖にいちばん出やすいので、まずここを直します。

打たないのは、短い主語・目的語・主題のすぐあとです。残すのは、条件や理由の切れ目、節を並べる切れ目、読点がないと係り方を取り違える所の3つだけです。主語や目的語が長くて読点が欲しくなったら、語順を入れ替えるか文を分けます。

| 打った文 | 直した文 | 理由 |
|---|---|---|
| 検索APIは、社内の文書だけを返します | 検索APIは社内の文書だけを返します | 短い主題のあとは打たない |
| 利用者が書いた質問を、Agentが検索APIへ渡します | Agentは利用者の質問を検索APIへ渡します | 目的語を前に出したための読点。語順を戻せば要らない |
| 権限が足りないと、APIは403を返します | （そのまま） | 条件の切れ目なので残す |

- 主語のあとに打たない。NG「エディターは、原稿を保存します」→「エディターは原稿を保存します」
- 前置きのあとに打たない。NG「この例では、2つのロールを使います」→「この例では2つのロールを使います」
- 目的語のあとに打たない。NG「開始時刻を、参加者に知らせる」→「開始時刻を参加者に知らせる」
- 1文に読点は1つまで。2つ目が要るなら文を分ける。NG「アプリは、写真を読み込み、幅を調整し、画面に表示します」→「アプリは写真を読み込みます。幅を調整して画面に表示します」
- 並べる語は「や」か「・」でつなぐ。NG「ログ、メトリクス、トレースを見る」→「ログ・メトリクス・トレースを見る」
- 見出しとタイトルには読点を入れない。NG「SVGの直接編集が、PowerPointに近い操作になりました」→「SVGの直接編集がPowerPointに近い操作になりました」
- 呼びかけの読点も入れない。NG「〇〇さん、今日の予定です」→「今日の予定」
- リズムを刻むための読点を入れない。NG「見切れは、AIでチェック。」→「見切れはAIでチェック。」
- 残してよい読点は、条件節のあと（「保存する場合、」「〜のとき、」「〜ため、」）と、読点がないと係り方が変わる箇所だけ

## 文末・文の形

- 「〜もの」で終えない。NG「現場の声を集めたものです」→「現場の声とログです」。NG「これは鍵のようなものです」→ 何なのかを名詞で言う
- 「〜することができます」と書かない。NG「設定することができます」→「設定できます」
- 「〜が可能になりました」「〜を可能にします」と書かない。NG「1画面での確認が可能になりました」→「1画面で確認できます」
- 「〜を行います」「〜となります」のような翻訳調の文末にしない。NG「呼び出しの制御を行います」→「呼び出しを制御します」
- 名詞を重ねない。NG「精度検証支援の実施」→「精度の検証を手伝う」
- 「の」を3つ以上続けない。NG「本機能の導入の目的の説明」→「この機能を入れる目的」
- 限定のすぐあとに別の否定を重ねない。NG「あるのは検索機能だけ。編集機能はまだありません」→「今は記事を検索できます。編集機能は開発中です」（開発中と確認できた場合）
- 「AではなくB」の対句を何度も使わない。読者が実際に誤解しそうな場面に限る
- 前置きで主張を予告しない。NG「重要なのは、権限を分けることです」→「権限は利用者ごとに分けます」
- 読者との問答を演じない。NG「〜と感じたかもしれません。そのとおりです」→ 譲歩は地の文で短く書く
- イ形容詞に「です」をつけて言い切らない。NG「設定が難しいです」→「設定は手順が多く、〜」と前後をつなげて書き直す
- 推測の注意書きを先回りして足さない。NG「環境によっては503が返ることがあります」→ 実際に検証で起きたことだけ書く
- 確認していないことを事実のように書かない。材料にあることだけ書き、推測には（想定）をつける
- 見出しで結論を断定しない。本文に「予定」とあるなら見出しも断定しない
- 関数名やクラス名を地の文に使わない。NG 見出し「load()とsave()の使い方」→「ファイルの読み込みと保存」。識別子はコードブロックに書く
- 同じ語をくり返さない。NG どの手順にも「確認」と書く →「ファイルを開く」「件数を数える」と動作を書き分ける

## 表記

- 太字＋コロンの箇条書きを使わない。NG「- **利用者**: 質問を入力する」→ 文にするか、「役割／関わり方」の2列の表にする
- 太字は原則使わない。使うのは誤読を防ぐ否定など、1節に1〜2か所まで
- 見出しにコロンを入れない。NG「設計メモ: 通知の宛先」→「通知の宛先の決め方」
- ダッシュ（—、——、──、―）を使わない。挿入句も見出しも同じ。NG「作図入門 — 基礎編」→「作図入門（基礎編）」。ディレクトリツリーの「├──」は対象外
- 通し番号や章番号を飾りでつけない。NG「### 1. 準備」「STEP 01」「第1章」「1.1」→ 見出しの文だけにする。番号を残すのは、順番を入れ替えると失敗する操作手順だけ
- ページ内の話題は見出しで区切る。Marp で次のスライドに移るところには `---` を置く
- 見出しは体言止めか、扱う対象を指す句にする。NG「OIDCとは何か、なぜ必要か」→「OIDCが必要になる場面」
- 「〜とは」だけの見出しにしない。NG「自動保存とは」→「自動保存のタイミング」
- 扇動的な語を使わない。NG「核心」「論外」「衝撃の」→ 事実を書く
- 箇条書きは3〜4項目・2階層までにする。経緯や因果は箇条書きにせず文でつなぐ
- 略語を説明なしで使わない。NG「KB」→「Knowledge Base」
- 個人名を書かない。NG「〇〇さんが承認する」→「イベントの主催者が承認する」
- 例の名前に無機質なコード名を使わない。NG「ALPHA」「BRAVO」→ 題材にあった親しみのある名前
- AIが生成したことを示すマーカー（`<!-- [AI生成] -->` など）を原稿に残さない

## スライドのタイトル・リード・図

- タイトルに読点も句点も入れない。NG「ログは、いつ消えるか。」→「ログはいつ消えるか」
- 見出しを「〜こと」で終えない。NG「申し込む前に確認したいこと」→「申し込み前の確認事項」
- 表紙と章のタイトルは名詞句にする。NG「写真をどこに保存するか」→「写真の保存先」。本編のページタイトルは平易な文でよい
- タイトルに番号をつけない。NG「ルール1　元の写真を残す」→「元の写真を残す」
- 01・02の通し番号を飾りでつけない。順番に意味があるときだけ流れの図で見せる
- 同じ大きさの灰色カードを並べて1枚だけ色をつける形を使わない → 罫線で列を区切る・表にする・流れは矢印で見せる
- 大きな数字を3つ並べない。根拠のある1〜2個に絞る
- どのページも「タイトル＋2行のリード＋図」にしない。文章だけのページ・箇条書き・表・図を混ぜる。1文で済むリードは1文にする
- 背景や課題を短い箇条書きで説明できるページは、見出しと箇条書きだけでよい
- 中身の薄いページを作らない。リード1行と結論1行だけで下半分が空くなら、図か表を入れるか前後のページへまとめる
- 図の中にまとめの一文や注記を書かない。言いたいことはリードに書く
- 章の扉ページを凝らない。章の名前だけをシンプルに
- リードと箇条書きで同じことを言わない
- 宛先をタイトルで分かるようにする。NG「当日のお願い」→「登壇者へのお願い」。同じ相手を指す語は資料の中で1つに統一する
- アップデート紹介では「これまで／今回から」の図を同じ配置で並べ、何が変わったかを見せる
- 冒頭で取り上げた問いには、その登壇の中で答える
- 聴き手がふだん使う言葉を選ぶ
- 1行は全角39字までにし、リードは文の切れ目で改行する。語尾の「す。」だけが次の行に落ちたら言い回しを直す

## 確かめ方

書いたら次の順で確かめます。

1. キットのフォルダーで `pnpm slides check <slides.md> --verbose` を実行する。自分が書いた文は `ai-comma` の読点と `ai-phrase` の言い換えを1件ずつ見直す。`ai-comma` はリード・箇条書き・表のセルで、短い主語や目的語のすぐあとの読点と、1文に2つ以上の読点を指摘する。長い主語や目的語のあとの読点がリードの1割を超えたときも、資料に1件だけ出る。番号の飾りは `ai-serial`、大きな数字の並べすぎは `ai-three-numbers`、同じ形のページの連続は `ai-monotone`、表紙と裏表紙の「Your Name」は `placeholder` に出る
2. 検査で見つからないものは、資料のフォルダーで原稿を検索する
   - 太字＋コロン：`rg -n '\*\*[^*]+\*\*\s*[:：]' slides.md`
   - 見出しの番号：`rg -n '^#+\s*(第?\d+[.章]|STEP|0\d)' slides.md`
   - 見出しのコロンと読点：`rg -n '^#+ .*[:：、]' slides.md`
   - ダッシュ：`rg -n '—|──|―' slides.md`（ツリーの├──は除いて見る）
   - 〜もの・することができ・を行います：`rg -n 'ものです|ためのもの|することができ|を行います' slides.md`
3. キットのフォルダーで `pnpm slides notes <slides.md>` を実行する。タイトルとリードを通して読み、主語と述語が対応しているか、声に出したときに不自然な切れ目がないかを見る。図と本文を隠しても筋が通るかも見る
4. 予告した件数と表の行数、番号の飛び、図と本文の数字が合っているかを数える
5. 実際の大きさで全ページを開き、同じ形のページが続いていないかを見る
