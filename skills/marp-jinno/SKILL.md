# 神野さん風のスライドをMarpで作る

キットは `{{KIT}}`。リポジトリから直接読む場合は、このスキルを含むリポジトリのルートを使う。以下のパスとコマンドはキット基準で、`node marp/bin/slides.mjs` を `slides` と略す。

仕上がりの基準は同梱の作例3本（`examples/gallery/` の jev-guardrail・rag-webinar・cognito-cimd）。どれも図のページが約7割、表のページは0〜2枚、箇条書きだけのページはない。タイトルとリードだけを続けて読んでも話がつながり、図には「誰が・何を・どこへ・どの条件で」が描いてある。

## 読む順番

作り始める前に次を上から読む。

1. [話の組み立てとリード](references/story.md)。一つの具体例を通す・ページごとに役割を変える・リードだけで筋が通る
2. [型と見本のページ](references/types.md)。型ごとのページの並びと、同じ役割の作例ページの対応表
3. アップデート紹介なら [アップデート紹介の型](references/update.md)。今まで → 何が変わったか → 何がうれしいか を図で見せる
4. キットの `docs/japanese-rules.md`。とくに「読点」と「スライドのタイトル・リード・図」の節
5. [図の選び方](references/figures.md)。表で済ませない・役者と吹き出し・配色・大きさ
6. [作図の部品](references/parts.md)。`scripts/jfig.py` の使い方と、型ごとのコード
7. [AWSの公式アイコン](references/aws-icons.md)。取得のしかたと図への入れ方

部品の正確な書式（表紙・会話・帯など）はキットの `docs/cheatsheet.md` にある。

## 作業の流れ

1. 一次資料を読む。アップデートなら What's New と公式ドキュメントから、発表日・対象・提供範囲・設定名・手順・料金・制約・記事の中の具体例を抜き出す。書いていないことは書かない。料金や地域が記事にないなら「記事に記載なし」と書く。推測には（想定）を付ける。
2. 発表者の名前を決める。依頼に名前がなければ利用者に聞く。聞けないときは `git config user.name` を使う。`slides new` は `--author` か git の user.name で表紙と裏表紙の名前を入れる。「Your Name」のまま出さない。
3. 一つの具体例・聴き手・読後にできることを決め、ページの表を書く。各ページに「タイトル（読点なし）」「リード1〜2文」「図の型（下の表から選ぶ）」「見本にする作例のページ」を1行ずつ書く。この段階で「図のページの割合」と「表のページの数」を数え、下の目安を満たしてから作り始める。
4. 雛形から資料を作る。`slides new <資料フォルダー> --template update --title "…" --author "…"`（型は `slides templates`）。雛形の文・`figs/` の図・`figs/src/make_figs.py` は見本なので、すべて題材に合わせて書き直し、使わない図は消す（残すと `figure-orphan` に出る）。雛形の `make_figs.py` は jfig を使っていないので、先頭の `# /// script` の見出しだけ残して jfig で書き直す。
5. 公式アイコンを用意する。AWSのサービスを図に描くなら、先に `slides icons fetch`（初回だけ）を実行し、`slides icons find <語>` で名前を確認する。取得できない環境はキットの `docs/aws-icons.md` の手動の手順を使う。
6. 図を描く。作図スクリプトを `figs/src/make_figs.py` に書き、先頭で `from jfig import *` する。`slides figs <slides.md>` で図を作り直し、図の文字を検査する（`slides figs` は jfig を読めるようにして実行する）。表紙の挿絵 `figs/cover-art.svg` も同じ `make_figs.py` の中で `scripts/cover_art.py` を使って題材に合わせて描き直す（[作図の部品](references/parts.md) の「表紙の挿絵」）。
7. 検査して目で見る。`slides check <slides.md> --contact --verbose` で error を0にし、warn と info を1件ずつ直す。`.check/contact-01.png` で全体を、`.check/pages/pNNN.png` で図のページを実寸で見る。見本にした作例のページ（PDFは `examples/gallery/<名前>/<名前>.pdf`、Readツールでページ指定して開ける）と並べ、図の大きさ・文字の量・アイコンと吹き出しの数が同じ水準か比べる。足りなければ図を描き直す。
8. `slides notes <slides.md>` でタイトルとリードだけを通読し、論理の飛躍と読点の多さを直す。依頼に応じて `slides build <slides.md>` でPDFとHTML、`--pptx` でPowerPointを出す。

## 仕上がりの目安（作り終えたら数える）

| 項目 | 目安 |
|---|---|
| 図（SVG）のページ | 本文のページ（表紙・裏表紙・章扉を除く）の6割以上 |
| 図の大きさ | 描いた範囲が本文の幅いっぱい（スライド上で1000px前後）、高さ340〜420px。`![h:N]` の N は図の高さ（`Fig` の第2引数）と同じにする。図の下からフッターまでの空きは80px前後まで。小さい図は `figure-small` に出る |
| 表のページ | 本文のページの1割まで。値の一覧（地域ごとの値・料金・設定のキーと値）に限る。続けて置かない |
| 箇条書きだけのページ | 0。背景や注意点も図・吹き出し・会話にする |
| 人やAgentの線画 | 場面・前後比較・構成図のどれにも1つ以上 |
| AWSのサービス | 公式アイコンで描く（汎用の箱や自作の絵にしない）。同じ図の中では大きさをそろえる |
| 灰色の吹き出し | 場面と前後比較と構成図に1〜2個。人の疑問・依頼か、サービスの条件を書く |
| 前後比較 | アップデート紹介では必ず入れる。「今まで」と「これから」を同じ座標で描く |
| リード | 1〜2文。1文の読点は1つまで。短い主語・目的語のあとに打たない |
| 表紙・裏表紙 | 発表者の名前が入っている。挿絵は題材の仕組みを描いている |
| 検査 | `slides check` で error 0。warn は直すか、直さない理由を言える |

## 表紙と裏表紙

表紙と裏表紙は同じ骨組みで組む。左の幅620pxに文字を置き、右の560×720の面に挿絵を一つ置く。面の色・28px間隔の点・2本の円弧はテーマが描くので、挿絵は透明な地に題材の主役だけを描く。

挿絵の語彙は白いカード、淡い棒、つなぐ線、主役の面（アクセントで塗る。1枚に1〜2つ）に限る。立体、影、窓の飾り（丸い3つの点やタイトルバー）、アイコンの羅列、英字の見出し、四隅の印は描かない。部品は `scripts/cover_art.py` にある。色はPetrolで指定し、`slides figs` か `uv run marp/scripts/figure_palette.py <資料>/figs` でPaperの色を足す。

肩の `kicker` には資料名（サービス名など）を書き、`span` に日付・イベント名・持ち時間を書く。`sub` は題名の下の一言、`who` は太字の名前と読み（例 `<b>神野 雄大</b>Yudai Jinno`。下の見本の `{{…}}` は発表者の値に置き換える）。裏表紙は題名の位置に「ありがとうございました」、その下に連絡先のリンクを置き、肩・署名・挿絵は表紙と同じにする。

```markdown
<!-- _class: cover cover-talk -->

# 失敗した集計だけを<br>再実行する

<p class="kicker">夜間集計 <span>アップデート解説</span></p>

<p class="sub">架空のクラウドサービスを例に<br>失敗した集計のやり直し方を紹介します</p>

<p class="who"><b>{{名前}}</b>{{ローマ字の読み}}</p>

![三つの集計のうち失敗した一件を再実行する](figs/cover-art.svg)

---

<!-- _class: closing back-cover -->

# ありがとうございました

<p class="kicker">夜間集計 <span>アップデート解説</span></p>

<p class="who"><b>{{名前}}</b>{{ローマ字の読み}}</p>

![三つの集計のうち失敗した一件を再実行する](figs/cover-art.svg)
```

題名は全角で1行11字前後（英字は2字で全角1字）で `<br>` を入れて2〜3行にし、表裏を実寸で並べて改行と署名の位置を確かめる。章扉まで濃い色で通す登壇（`layout: stage`）では右の面だけが濃くなる。見本は `docs/covers.md` にある。
