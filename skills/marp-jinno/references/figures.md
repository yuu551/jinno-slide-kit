# 図の選び方

まず、聴き手が図で追う一つの動作を書く。たとえば「在庫を調べる」なら、誰が質問し、どのツールにどの引数を渡し、何が返るか。箱の名前を並べる前に、行き先・戻り先・処理を止める位置を決める。

## 表で済ませない

表は項目を横に読み比べるときの形。関係・順序・前後を追う話を表にすると、読み手は自分で頭の中に図を描き直すことになる。

| 伝えたいこと | 表にしない。こう描く | 部品 |
|---|---|---|
| 流れ・手順の順序 | 役者を横に並べ、上から下へ要求と応答。または番号つきの手順 | `icon` `aws` `A` `steps` |
| 変更前後 | 同じ座標の2枚（または左右）。変わった線と箱だけ塗る | `head` `box` `frame` `bubble` |
| 構成 | 人・Agentの線画、公式アイコン、境界の枠、経路のラベル | `icon` `aws` `frame` `A` `bubble` |
| 条件による分岐・許可と拒否 | 2段の経路。通す側は結果まで、止める側は手前で× | `A` `blocked` `ok` |
| 役割の違い | 役者ごとの列か、人と道具の対応の図 | `icon` `card` |
| 注意点・制約 | 注意点ごとに、どこで何が起きるかの小さな図と⚠ | `warn` `blocked` `bubble` |
| 背景・課題 | 場面の図（人の困りごとを吹き出しで） | `icon` `think` `bubble` |
| 締め | 列ごとの見出し・短い説明・要点の図 | `card` `head` |

表にしてよいのは値の一覧だけ。地域ごとの値、料金、設定のキーと値、観点ごとの比較（何がうれしいか）。行がどれも同じ形で、1行を横に読めば済むもの。それでも表のページは本文の1割まで、続けて置かない。迷ったら作例を数える。CIMDは58枚で表は2枚、RAGは84枚で0枚。

箇条書きだけのページも作らない。3〜4項目の箇条書きにしたくなったら、項目を役者や場所に置き直して図にするか、人とAgentの会話にする。

## 役者・アイコン・吹き出し

- 人は頭と肩の線画（`user`）、Agentはアンテナ付きの顔（`agent`）、文書は折り返しのある紙、保存先は円柱。役割名をアイコンの下に書き、枠の中に何度も名前を重ねない。
- AWSのサービスは公式アイコン（`aws()`）。汎用の箱や自作のロゴにしない。公式アイコンが取得できないときだけ、`service` の線画とサービス名で描く。存在しないサービス名をロゴらしい図形で作らない。
- 同じ図の公式アイコンは同じ大きさ（64前後）にそろえる。主従は位置と枠の塗りで示す。
- 灰色の吹き出しは1〜2行。人の吹き出しは具体的な依頼や疑問、サービスの吹き出しは条件。尻尾は話し手の頭・アンテナ・アイコンの外周まで届かせる。線やラベルと交差するなら吹き出しを空いた側へ動かす。
- 考えごとの雲（`think()`）は声に出す前の迷い。発言とは描き分ける。
- アイコンと下の名前をまとめて一つの占有領域として扱う。矢印や吹き出しをその中に通さない。
- サービスに人のせりふを言わせない。題材に登場しないAgentを説明役として経路に足さない。

## 役割ごとの色

| 役割 | Petrol（図はこの色で描く） | 使う所 |
|---|---|---|
| 主役 | 線 #4a8399、文字 #2f6273、面 #edf4f6 | この図で追う枠・今回の機能・強調する1つの箱 |
| Agent・許可の経路・成功 | 緑 #2e8b6f | Agentの線画、通す経路、✓ |
| 止める・注意・失敗 | 橙 #c2703d | ×、⚠、止める経路、遅い・手間の数字 |
| 外部のサービスを描き分けるとき | 紫 #6f5ba6 | 出番は少ない |
| ふつうの線と文字 | 濃灰 #232f3e・#545b64、補足 #5f6b76 | 矢印の大半、ラベル |

- 1つの図で淡い面を塗るのは1〜2個まで。残りは白地に細い灰色の線。
- 線に色を付けるのは、通す経路と止める経路を描き分けるときだけ。ふつうの流れは濃灰。
- 対比の図で片方だけ強調すると、強調しない側が悪く見える。今まで／これからは「これから」の主役だけを塗る。
- 公式アイコン・写真・画面キャプチャは元の色のまま。役割の色で上書きしない。
- 図は Petrol の色で描く。`slides figs` が Paper の色を足すので、原稿の `theme:` を切り替えるだけで両方のテーマに合う。許可・拒否の緑と橙は両テーマで共通。

## 大きさと文字

- 図は大きく描く。作例の図のページでは、描いた範囲がスライドの上で幅1000〜1140px・高さ350〜370px（中央値）、図の下からフッターまでの空きは60〜70pxだった。これより小さい図は文字も小さくなり、ページが薄く見える。
- 幅1160、高さは中身に合わせて340〜420。Markdownでは `![h:N](figs/x.svg)` の N を図の高さ（`Fig` の第2引数）と同じにする。N を小さくすると横も一緒に縮む。リードが2行でページに収まらないときだけ、N を10〜20ずつ下げる。
- 1段で低い図（高さ250以下）になったら、下に値の例・条件・結果の段を足して縦を使う。左右に大きな余白が残るなら、役者の間隔を広げて幅いっぱいに置く。`slides check` は、描いた範囲が幅720px未満、または高さ200px未満で下が170px以上空く図を `figure-small` で知らせる。
- 主なラベルは20〜24px、補足は17〜18px。16px未満は使わない（`svg-text-small` に出る）。
- 文字は text/tspan のまま。長い日本語やAPI名は意味の切れ目で `\n` を入れて改行する。
- 枠と文字、箱と箱の間を空ける。矢印の線・矢じり・ラベルが触れない幅を先に取る。起点と終点は箱の辺から6〜8px離す。
- 大きな図を本文の幅いっぱいに広げる。外に大きな空白を残したまま中央の図を小さくしない。ページの下半分が空くなら、図の縦を使って中身（値の例・条件・結果）を足す。
- 図の中にスライドと同じタイトルや結論の帯を置かない。

## 確かめる

`slides figs <slides.md>` が図の文字の重なり・はみ出し・小ささを検査する。検査が通っても、線がラベルを横切る、尻尾の向きが違う、矢印が逆向き、×の先に線が続く、といった誤りは機械では出ない。`slides check --contact` の `.check/pages/pNNN.png` を実寸で開き、見本の作例のページと並べて、往路・復路・止める位置・名前を指でたどるように読む。
